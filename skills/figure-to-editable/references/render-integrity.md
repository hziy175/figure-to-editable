# 保存、缓存与渲染一致性

## 原生应用与辅助预览

PowerPoint 应用内渲染最直接，但不应虚构其可用性。离线预览允许采用能解析 PPTX 的工具，记录名称和限制。图形脚本单独绘出的“理想图”不能充当 PPTX 保存状态的预览。

对于不支持的自由路径、径向渐变和透明度，辅助渲染必须从最终 PPTX 的实际 XML 读取几何及样式。不要从生成前计划重新绘图来掩盖错误。未实现的效果显式列为限制；必要时保留工作草稿，或使用可用的原生渲染检查。

## 原生几何注意事项

- 点、路径和编辑边界单位统一。水平/垂直路径仍使用适度非零边界，不能让边界四舍五入到零。
- 浏览器的 SVG `viewBox`、CSS 大小和 `preserveAspectRatio` 必须对应原生坐标。极细画布在 `meet` 模式下可能缩短线段，表现为误差线主体与端帽分离。
- 对线段检查最终实际端点，不仅检查包围盒。对组内对象应用父组偏移/缩放/旋转；未实现组变换的核查代码必须报告不支持。
- 普通描边与虚线单位跟随统一缩放。禁止把同一字体大小同时按两套规则缩放，特别是公式上下标。

## 防止旧状态混入

原生工具、OfficeCLI 或预览服务可能持有文档状态。外部修改 XML 前先保存并释放相应文档；不确定旧会话是否会覆盖磁盘文件时，先保留修改后的副本，再关闭旧会话。重新打开最终文件，核对一个实际变化的属性，不能只依赖“命令成功”。

不要假设所有版本都缓存，也不要为无证据的问题反复清缓存。只在新字号、形状或保存状态未出现在预览时诊断。

## 指纹流程

1. 保存最终 PPTX，计算 `deck_sha256`。
2. 从该文件渲染，检查导出的图片。
3. 重新计算 PPTX 指纹，确认与步骤 1 一致。若不同，重做渲染与检查。
4. 记录源图、PPTX、预览各自的 SHA-256、渲染器和视觉复核记录。
5. 用最终文件、最终清单、最终预览执行审计。此后任何修改都使先前的检查失效。

时间戳只作辅助判断。指纹能检测文件替换或陈旧记录，不能单独证明“预览确由 PPT 渲染”，也不能证明视觉忠实；渲染过程和实际对照仍需要可靠执行。
